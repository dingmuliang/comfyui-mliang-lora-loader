📋 项目起源

用户希望在 ComfyUI 中拥有类似 WebUI 的 LoRA 管理体验：文件夹分组浏览 + 预览图 + 多槽位加载，且全部集成在一个节点内。现有的 rgthree / Lora-Manager 等插件要么功能分散，要么交互不满足需求。于是从零开始开发这个自定义节点。

⚡ 核心技术难题与解决方案

🔴 难题1：ComfyUI combo widget 不支持动态更新

标准 combo widget 的 options.values 修改后，DOM <select> 元素不会自动同步。这是 LiteGraph 的架构限制，不是逻辑错误。

解决：放弃 combo widget，使用 addDOMWidget API 构建完全自定义的 DOM 界面。

🔴 难题2：this.element 在秋叶整合包中为 undefined

秋叶 v1.7 的 LiteGraph 版本不给节点设置 element 属性，导致所有依赖 this.element.querySelector() 的代码全部失败。

解决：使用 addDOMWidget API，它会自动管理容器 DOM 的挂载。

🔴 难题3：hidden 字段不创建 widget 对象

INPUT_TYPES 的 "hidden" 字段在秋叶版本中不会被实例化为 widget 对象，导致 JS 的 this.widgets.find() 永远找不到。

解决：改用 "optional" + JS 中 display:none 隐藏 DOM 元素。

🔴 难题4：ES module import 在 ComfyUI 环境不可用

用 export const TREE_DATA + import 传递数据在 ComfyUI 的 JS 加载链中失败。

解决：Python 写入 window.__LB_TREE__ = ... 全局变量格式，JS 直接读取。

🔴 难题5：JSON 黑框污染 UI

addDOMWidget 的 getValue() 返回字符串时，ComfyUI 会自动创建一个文本框显示它。

解决：getValue() 返回数组而不是 JSON 字符串。ComfyUI 只对 STRING 类型显示文本框。

🔴 难题6：file:// 预览图被浏览器拦截

用 file:///C:/Users/... 加载预览图被浏览器安全策略拦截。

解决：Python 注册 /mliang-lora/preview?h=hash API 路由，用 MD5 hash 编码路径，通过 aiohttp FileResponse 返回图片。

💡 经验教训

最重要的教训：看报错日志，不要猜。错误日志明确写了 element=false，但在那之后我绕了三个错误方案（onAdded → rAF轮询 → onDrawForeground），每一个都在赌"这次 this.element 应该能拿到"。正确的做法是直接分析报错 → 换方案 → 一步到位。
教训具体案例
先研究框架，再写代码 花了一整天在 combo widget 上打转，最后发现这是框架硬限制。如果一开始就研究 Lora-Manager 的源码，能省 80% 的时间。
不要对抗框架 试图给 combo widget 动态更新 options → 操作 DOM → 时序冲突 → 永远不稳定。应该直接走框架提供的 addDOMWidget 路线。
数据通道和 UI 通道分离 最终方案用两个 widget：一个 STRING widget 传数据给 Python（隐藏），一个 DOM widget 负责 UI（显示）。清晰分离，互不干扰。
__init__.py 要备好份 Python 文件多次丢失，每次都要重写。现在有 git + GitHub 双保险。
inline 样式 > 外部 CSS ComfyUI 加载顺序不确定，外部 CSS 文件可能未加载。inline 样式 100% 可靠。
代理问题 火绒/系统代理拦截 GitHub。走代理 git config http.proxy "http://127.0.0.1:10090/" 绕过去了。
